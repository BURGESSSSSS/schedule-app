# 技术决策记录

## 取件码 M2：数据旁听管道（1.2.0）

- 目标：拿到菜鸟/淘宝包裹页真实的数据结构，为自动解析取件码做适配。约束：不伪造请求、不逆向签名、不碰密码——让页面自己发请求，我们只旁听。
- 技术方案：WebView 主文档 GET 自取一份（带同一 cookie、Accept-Encoding: identity），在 `<head>` 后注入 JS 钩子，重写 `XMLHttpRequest` 与 `fetch`，把页面收到的 JSON 经 `addJavascriptInterface` 桥接回应用，追加写入 `files/pickup_capture.log`（总量封顶 2MB）。
- 关键坑：多数站点 CSP 会拦内联脚本，仅靠主文档注入钩子不执行；补了 `onPageStarted` 里的 `evaluateJavascript` 第二注入（不受页面 CSP 限制）后管道打通，已在模拟器用微博页实测捕获到全部 XHR JSON。钩子含 1.5s 心跳（`__bridge_test__`），导出文件里有无这条可判断钩子是否运行。
- 导出：取件码页「导出抓包数据」经 FileProvider 走系统分享，用户把文件发给开发者即可离线适配解析。
- 仿真器无法登录淘宝（无短信验证码），真实包裹页 JSON 结构仍需真机采集：登录 → 「包裹列表」→ 浏览 → 导出发回。

## 取件码功能 M1：包裹页直显（1.2.0）

- 定位与入口：取件码是支线功能，主列表放「更多」页（与课程提醒并列），「今日」页仅在有未取包裹时显示一张快捷卡片（条数 + 最新一码 + 一键复制），无包裹时完全不出现；不加第四个底部 Tab。
- 数据：Room 升到版本 5，新增 `pickup_codes` 表（code/station/status/picked/createdAt），与课程数据隔离；应用内列表复制走系统剪贴板。
- 包裹页方案：内嵌 WebView 打开淘宝移动版（m.taobao.com），登录在淘宝官方页面完成，密码不经过本应用，会话 cookie 由系统 CookieManager 持久化；返回键优先走网页历史。
- 关键坑：淘宝 H5 会把未知深链 302 到 App 推广页，因此放弃菜鸟深链改用移动版首页（真机上再调更短深链）；H5 偶发 302 到明文 http，通过 network_security_config 仅对淘宝系域名放行明文流量；非 http scheme（taobao://、intent://）不在 WebView 内加载。
- 已知边界：自动获取取件码（通知监听/页面解析）是下一步 M2/M3，需要真机登录后抓真实数据结构才能实现； emulator 无法登录淘宝做自动化验证，M1 只验证了容器与页面加载。

## 界面全面改版为 OpenAI 式视觉语言（1.1.0，重做后）

- 设计基准：白底黑字细线（#0D0D0D 墨色 / #6E6E80 次级灰 / #F7F7F8 浅灰面 / #ECECF1 细线），唯一强调色为绿色 #10A37F，仅用于「正在进行」「下一节课」状态标识；优先级为可读性 > 简洁 > 科技感。
- **固定浅色主题**（不跟随系统深色模式）。改版第一版在深色手机上出现黑底黑字的不可读界面，根因是界面组件硬编码浅色常量而未走主题系统；在为深色模式专门设计一整套对比关系之前，浅色是唯一基准。
- **周视图课程格回归底色块**：课程色的低饱和底（alpha 0.16）铺满格子，文字全宽显示。改版第一版曾用「左侧细色条 + 白底」，在 5 列窄格里挤掉了课名空间导致全部截断——窄格子中信息密度优先于装饰；色条方案只适合宽卡片，宽卡片处已全部改为小圆点标识。
- 玻璃拟态卡片（半透明+白描边）替换为纯白卡片 + 1dp 细线边框 + 圆角（AppCard）；波浪背景动画彻底移除，全局纯白底。
- 底部导航从 Material NavigationBar 换成自绘扁平样式（细线分隔、黑/灰两级状态、无胶囊指示器）；页头按钮改为胶囊形（实心黑=主要/确认态，浅灰=次要）。
- 周网格容器为浅灰圆角面板，空格子无边界（编辑模式才显示白底加号），今日表头用黑色胶囊。
- 主题三个文件（Color/Theme/Type）整体重写：去掉动态取色，正文/标题字号在 Type.kt 统一定义。
- 开发日志为三级导航：「更多 → 开发日志」进版本选择页（V1.0.0 式小条列表），点条目滑入三级公告详情页；系统返回键逐级回退（详情 → 列表 → 更多）。
- 新导入/新建课程按 id 分配稳定色；读取已有记录时优先保留数据库中的 colorValue，避免覆盖旧课程的既有视觉标识。
- 教训两条：全局重命名避开短单词（`Edge → Hairline` 曾误伤 `enableEdgeToEdge`，子串冲突）；界面颜色必须走 MaterialTheme 角色，硬编码常量在第二主题下必然失控。

## 性能：背景光幕改为静态绘制（1.0.1）

初版背景是无限循环的波浪动画并叠加 26dp 全屏实时模糊，每帧都要重算整个屏幕的模糊，导致滑动掉帧和持续发热。1.0.1 改为静态绘制：同样的波浪和配色，只在首帧画一次，去掉实时模糊和逐帧动画。滚动时暂停动画的旧方案（isWeekScrolling）随之移除。

## 正式版签名沿用调试密钥（1.0.1）

正式版打包目前使用 Android 自动生成的调试密钥库（配置在根目录 `keystore.properties`），这样正式版可以直接覆盖安装调试版，保留用户已录入的课程数据。签名不影响运行性能；以后要对外发布（发给同学、上架应用商店）时，需生成独立密钥库替换 `keystore.properties` 中的四项配置，届时用户需要一次性卸载重装。

## 打开正式版 R8 优化（1.0.1）

`app/build.gradle.kts` 中 release 的 `optimization` 从 `enable = false` 改为 `enable = true`，打包时执行代码裁剪和资源收缩（APK 从约 60MB 降到约 47MB）。

## 使用 Kotlin 和 Jetpack Compose

这是 Android 官方重点维护的现代 UI 方向，适合从一个小型应用开始学习。界面用 Compose 编写，状态由 ViewModel 管理。

## 使用 Room 保存课程

课程是结构化数据，需要按星期、周次和时间查询。Room 比直接保存一大段文本更适合后续修改、筛选和升级数据结构。

## 使用 DataStore 保存设置

学期开始日期、默认提醒时间等属于轻量设置，不和课程记录混在一起。

## 使用系统文件选择器导入

通过 Android 的系统文件选择器读取用户主动选择的文件，不需要申请读取整个存储空间的权限。

## 通知策略

第一版不做闹钟功能，只做课程通知。后台调度使用 WorkManager，接受系统为了省电而延迟执行。WorkManager 适合可靠但不要求精确到秒的后台任务，并且任务可以持久化和恢复。

如果实际使用后发现提醒必须非常准时，再单独评估非精确 AlarmManager 或精确闹钟权限。这个决定不能提前假设，因为不同 Android 版本和手机厂商的省电策略会影响结果。

## 先做 CSV，再做 XLSX

CSV 更容易验证，也更适合先把“选择文件、解析、预览、确认、写入”整条流程做通。等第一版稳定后，再增加 XLSX 解析，避免一开始被复杂文件格式拖住。

## 不做服务器

课程表和提醒都可以在本地完成。第一版不加入账号和服务器，减少学习成本、隐私风险和部署工作。
