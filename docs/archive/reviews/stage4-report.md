# 阶段 4：周视图

## 1. 大白话总结

周视图现在按五列固定宽度排版，时间轴固定在左侧；只有本周有周六或周日课程时才出现周末两列，并可在“工作日 / 周末”两个端点之间横向切换。头部保留编辑、导入、复制到下周和切周功能，左右图标也有明确的无障碍描述。

同一列内相交的课程会先组成一个连续时间组，再按课程顺序堆叠，因此长课不会吞掉后面的课程。相交组内每张卡增加紧凑的“1–6节”小字，说明堆叠后的卡片仍对应哪段真实课时；详情弹窗和读屏描述继续使用课程的真实开始、结束节次和地点。设计预览新增了不会写入数据库的周视图假数据，其中包含 0–5 节长课与 2–3 节嵌套课反例。

窄屏和 1.3 倍字体下，拉丁课程简称、时间轴时间和教室号按实际测量统一缩小，最低 8sp；普通 `Node.js`、`08:00`、`AB-302` 可完整显示。极长的 `IntroductionToComputing` 到达 8sp 下限后仍会省略，以避免缩成不可读的极小文字。

## 4. 与意见书不一致之处及原因

- 相交课程组采用“连续组内按顺序堆叠”的显示折中。长课和嵌套课共享一个组的总高度，组内单张卡的几何高度因此不再等于真实课时跨度；每张相交组卡增加紧凑的“1–6节”提示，并保留详情及读屏中的真实时段，避免用户只凭外侧时间轴误读。把相交课程做成真正的并列轨道会破坏五列固定宽度和 360dp 可读性，因此没有在阶段4大改网格。
- `FittedWeekText` 的最小字号设为 8sp。它让普通拉丁简称、时间和房间号在 360dp/1.3 倍字体下完整显示；`IntroductionToComputing` 仍超过可读宽度而省略。课程可通过已有周视图简称字段提供更短的显示名。
- §5.3 的六条性质仍未满足或未验收，原因是阶段顺序要求阶段4只完成周视图，详情转场必须在阶段5单独实现和检查。

## 5. 请使用者在真机上检查的清单

1. 调试版打开“更多” → 滚到底部 → “设计预览” → “周视图假数据”。应看到五个工作日、保留的编辑/导入/复制按钮和左侧固定时间轴。该沙盒的课程点击、导入、复制回调是空实现，只用于布局与文字检查，不用于验收详情或数据操作。
2. 将屏幕设为约 360dp、系统字体 1.3 倍，在假数据周视图查看周一课程。`Node.js`、`08:00`、`AB-302` 应各自单行；`IntroductionToComputing` 可显示为省略文本，不能出现时间换行或房间号被拆成多行。
3. 点击“周末 ›” → 应滚动到周三至周日，并变成“‹ 工作日”；点击“‹ 工作日” → 应回到周一至周五。周六、周日列宽应与工作日相同。
4. 在假数据沙盒的周末端点查看周日反例 → 长课和嵌套课都应存在，各自有“1–6节”和“3–4节”提示；这里仅检查布局和读屏文本，不期待打开详情。
5. 返回真实周视图后进入编辑模式，点击空格、已有课程、导入和“复制到下周”，确认原有回调与数据操作不变；点击真实课程确认详情入口和读屏描述包含完整课程名、时间和地点。
6. 在真实周视图切换浅色/深色检查课程色文字和中性空格是否清楚。详情形变的六条性质请留到阶段5专项验收。
