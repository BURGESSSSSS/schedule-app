# 开发路线

每一步都先运行和验证，再进入下一步。遇到问题时，优先修复当前步骤，不同时引入太多新功能。

## 第 0 步：准备环境

- 安装 Android Studio 稳定版
- 创建一个空的 Jetpack Compose 项目
- 在模拟器或真机运行默认页面
- 确认可以查看 Logcat

完成标志：默认应用能安装、启动、重新编译。

## 第 1 步：搭建应用骨架

- 建立首页、设置页、添加课程页
- 加入底部导航或顶部页面导航
- 先使用假数据显示课程表

完成标志：可以在几个页面之间切换，课程表布局稳定。

## 第 2 步：保存课程数据

- 设计 Room 数据表
- 加入课程的增删改查
- 使用 DataStore 保存学期开始日期和默认提醒设置

完成标志：关闭应用后重新打开，课程仍然存在。

## 第 3 步：完成周视图

- 根据学期开始日期计算周次
- 实现上一周、下一周、本周
- 根据单双周和起止周过滤课程

完成标志：切换日期和周次时，课程显示正确。

## 第 4 步：实现高亮

- 计算当前日期和时间
- 识别正在进行的课程
- 找到下一节课程
- 为课程卡片提供进行中、下一节和普通三种状态

完成标志：修改模拟器时间或使用测试时间后，高亮结果可验证。

## 第 5 步：实现通知

- 创建通知渠道
- 请求通知权限
- 使用 WorkManager 安排非精确提醒
- 课程修改或删除后更新、取消对应提醒
- 设备重启后确认提醒仍能恢复
- 加入一个“发送测试通知”按钮

完成标志：测试提醒能出现，课程提醒大致在目标时间附近出现，关闭提醒后不会继续发送。

## 第 6 步：实现 CSV 导入

- 使用系统文件选择器选择文件
- 读取并解析 CSV
- 校验表头、时间、星期、周次和单双周
- 显示导入预览
- 用户确认后写入数据库

完成标志：合法文件导入成功，非法文件有清晰错误提示。

## 第 7 步：打磨和测试

- 处理空数据、跨周、学期结束等情况
- 测试横竖屏和小屏设备
- 测试通知权限被拒绝的情况
- 测试省电策略导致的提醒延迟
- 测试应用升级后的数据保留
- 生成可安装 APK

完成标志：核心流程可以从新安装开始完整走通。

## 1.3.0 阶段 2/3 执行记录

本轮围绕现有单课表流程完善，不新增多课表产品或待办/组件功能：

- 课程数据继续使用现有 Room 表，导入替换通过 DAO 事务完成，避免清空后插入失败造成整周丢失。
- 当前时间按轻量定时刷新，跨日、跨时段后今日页和进行中/下一节标识会重新计算。
- 周视图默认保持周一至周五五列；仅当目标周存在周六或周日课程时，额外显示两列周末网格，避免压窄常规课程名称。
- 编辑/添加沿用现有对话框流程，增加教师、起止节次和清晰的课程名称校验；OCR 导入仍先预览再替换目标周。
- 取件码、包裹页和既有课程数据库不迁移、不清空；提醒底层由独立通知任务提供接口后再统一集成验证。
